# 16-Week Learning and Development Roadmap

| Weeks | Learn | Build | Research output | Exit criterion |
|---|---|---|---|---|
| 1-2 | Goal drift, HTN, agent memory, empirical SE validity | Formal protocol and schemas | Literature matrix, preregistration | Constructs and primary outcome frozen |
| 3-4 | SWE-bench task lifecycle and agent interfaces | Single-agent and flat baselines | Pilot task manifest | Same task runner works for both baselines |
| 5-7 | Distributed contracts, state machines, provenance | Contracts, receipts, event log | Protocol section | Injected contract/state faults are blocked |
| 8-10 | LangGraph persistence, Git worktrees, merge semantics | Recursive runtime, verifier, integrator | Implementation section | Root-Worker-Leaf flow is reproducible |
| 11-12 | MCP and Codex extensibility, evaluation instrumentation | Skill, Plugin, MCP tools | Artifact documentation | Plugin and stdio MCP validation pass |
| 13 | Experimental design, contamination, power, qualitative coding | Screening runner and sealed manifests | Failure taxonomy | 24-task screening completes without leakage |
| 14 | Paired inference, cluster bootstrap, multiplicity | 120-task controlled confirmation and public sensitivity pipeline | Results tables | Frozen analysis consumes immutable raw JSONL only |
| 15 | TOSEM/EMSE argument structure and validity threats | Release automation | Full manuscript draft | Every claim maps to data or citation |
| 16 | Artifact evaluation and anonymous packaging | Reproduction bundle | Preprint/submission draft | Clean machine reproduces tables and tests |

Weekly practice: read two primary papers, implement one measurable invariant, add one adversarial test, review one failure trace, and update the claim-evidence table. Do not add protocol rules solely from intuition; each rule must address an observed failure or an explicit safety invariant.
